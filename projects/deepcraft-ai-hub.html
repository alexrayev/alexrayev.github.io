DEEPCRAFT™ AI Hub: From Three Tiers to Git-Driven Static Delivery

A catalog of edge-AI models, solutions, tools and partner projects, where each card is published straight from a GitHub repository.

The challenge

The AI Hub lets Infineon and its partners publish AI projects on public GitHub; each project appears as a card in the hub's web interface, with a link back to its repository. The original design, created by a third-party vendor, served the cards through three tiers: a React front end, a FastAPI middle tier and a PostgreSQL database, all running in Docker Swarm on a single EC2 host behind HAProxy. Every content change had to pass through the API and the database, and the host was one more server to patch, secure and keep running.

What I built

  • Removed the middle tier and the database. The card catalog is now a single master.json file generated from the GitHub repositories themselves.
  • Organised content as a main repository with Git submodules (model zoos for two microcontroller families, studio accelerators, partners, resources, images). Each card is a folder with a metadata.json file, following a documented card contract.
  • Wrote the catalog generator (Python): it walks the submodules, normalises titles and type keys, rewrites each card's GitHub link to its source folder, applies per-module title prefixes and orders cards by a configurable category order.
  • Built GitHub Actions pipelines for development and production: pull the latest submodules, generate the catalog, merge default images, upload to S3, invalidate the CloudFront cache and publish a copy of the catalog back to the repository. AWS access uses short-lived OIDC credentials, with no stored keys.
  • Rebuilt hosting as infrastructure-as-code with the AWS CDK (TypeScript): a private, versioned S3 bucket reached only through CloudFront (origin access identity), HTTPS redirect, Brotli and gzip compression, and separate development and production stages.
  • Kept the React web interface; it now loads the catalog from the CDN in a Web Worker, with no backend calls.

Outcomes

  • Designed, built and delivered in two weeks.
  • Two runtime tiers removed: no API servers and no database to run, patch, back up or secure.
  • Publishing a project means adding a folder to GitHub; the pipeline does the rest. The catalog served 93 cards.
  • Delivery runs on managed services (S3 and CloudFront) instead of a single server, with TLS at the edge and no open SSH port.
